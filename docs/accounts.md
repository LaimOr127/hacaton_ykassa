# Вход и синхронизация аккаунта

Откройте «Войти» на витрине. После входа в «Мои заказы» доступны история, переписка, текущая доля оплаты, чеки и подтверждения. Другой браузер или телефон должен пройти свой вход в тот же аккаунт. Данные сохраняются на сервере. Одновременно можно работать на нескольких устройствах и завершить текущий либо все сеансы.

Если заказ оформлялся гостем, на устройстве с прежней сессией войдите и нажмите «Перенести гостевые заказы с этого устройства». После этого гостевая ссылка и cookie больше не дают доступа к перенесённым заказам. Для входа с разных провайдеров добавьте каждый нужный способ из профиля. Привязку можно начать в течение 15 минут после подтверждения входа. Уже привязанные к другому аккаунту идентификаторы нельзя добавить повторно. Совпадение email у разных провайдеров само по себе аккаунты не объединяет.

Продавец входит в личный аккаунт и подтверждает действующий код магазина. Затем он может открыть тот же кабинет с другого устройства. Сервер проверяет назначение на каждом запросе. При выборе другого магазина старые формы кабинета требуют обновления. Выход со всех устройств завершает сеансы и сохраняет привязку магазина. Штатного отзыва отдельного назначения в локальном профиле пока нет.

## Настройка способов входа

Включите `ACCOUNT_AUTH_ENABLED=1` в `.env` и примените настройки командой `docker compose up -d --wait app`. В `.env.example` эта опция включена. Без переменной личные аккаунты выключены. Кнопки показываются после настройки соответствующего провайдера. Для публичного доступа используйте HTTPS и точные зарегистрированные адреса возврата. Не записывайте параметры запроса на маршрутах `/account/*` в журнал обратного прокси.

| Способ | Что требуется |
| --- | --- |
| Логин и пароль | Дополнительный провайдер не нужен. Пароль от 12 символов хранится в виде хеша scrypt с индивидуальной солью. |
| Почта | Настройте SMTP как для отправки документов, в режиме `live`. Одноразовая ссылка действует 10 минут и открывается в браузере, где запрошена. |
| Google | Зарегистрируйте веб-клиент OIDC и callback `PUBLIC_ORIGIN/account/oauth/google/callback`. |
| Яндекс | Зарегистрируйте OAuth-клиент с правом `login:info` и callback `PUBLIC_ORIGIN/account/oauth/yandex/callback`. |
| VK ID | Разрешите callback `PUBLIC_ORIGIN/account/oauth/vk/callback` у своего приложения. Используется PKCE, а обмен включает `device_id` и `state`. |
| Telegram | В BotFather зарегистрируйте веб-вход и callback `PUBLIC_ORIGIN/account/oauth/telegram/callback`. Используется OIDC без запроса номера телефона. |
| MAX | Создайте бота с мини-приложением по адресу `PUBLIC_ORIGIN/account/max/miniapp`. Задайте имя бота в `MAX_BOT_NAME` и токен в `MAX_BOT_TOKEN`. Мини-приложение проверяет подписанные данные MAX и показывает одноразовый код. Пользователь вводит его в исходной вкладке. |

Для OAuth заполните `SOCIAL_AUTH_JSON` объектом, где ключи `google`, `yandex`, `vk`, `telegram` сопоставлены массивам из идентификатора приложения и секрета. Можно указать только подключённые провайдеры. Для публичного клиента VK ID второй элемент допускается пустым. Храните значения в защищённой конфигурации развёртывания.

Официальные описания. [Google](https://accounts.google.com/.well-known/openid-configuration) · [Яндекс](https://yandex.ru/dev/id/doc/ru/user-information) · [VK ID SDK](https://github.com/VKCOM/vkid-web-sdk) · [Telegram](https://core.telegram.org/bots/telegram-login) · [MAX Bridge](https://dev.max.ru/docs/webapps/bridge/) · [Подпись MAX](https://dev.max.ru/docs/webapps/validation/)

## Закрытый профиль и данные прежних версий

В `private` действует корпоративный вход через OAuth2 Proxy. История покупателя привязана к проверенной паре `issuer + subject`. Администратор приложения задаёт назначение магазину через `OIDC_MERCHANTS_JSON` по идентификатору `sub` из IdP. Публичную регистрацию и социальные входы приложение в этом профиле не принимает.

Обновление добавляет таблицы и сохраняет идентификаторы заказов и платёжных попыток. При переносе гостевая сессия отзывается. Проверьте резервную копию перед развёртыванием. При временном отключении личных аккаунтов перенесённые заказы сохраняются, но требуют повторного включения аккаунтов для доступа. Перед откатом на старую версию учитывайте, что она не умеет читать историю аккаунта. [Развёртывание](production.md)
