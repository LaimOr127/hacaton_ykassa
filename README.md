# Заказ из переписки

ИИ-агент для компаний, принимающих заказы в чате. Покупатель описывает пожелания и меняет заказ обычными сообщениями. Приложение сверяет запрос с каталогом продавца, рассчитывает стоимость и предоплату. После подтверждения конкретной версии заказа агент создаёт платёж через MCP ЮKassa и проверяет его результат.

Проект готовится для трека «Интегратор». Команда из двух человек проверяет переносимость на разных типах бизнеса. У кофейни клиент меняет количество завтраков и состав набора. У клининга он выбирает услугу по площади и оплачивает долю стоимости. Оба магазина используют одну готовую языковую модель и один механизм расчёта.

## Статус

Можно начать заказ в кофейне или подключить новый магазин через кабинет. Покупатель пишет заказ, согласует состав и получает подтверждение оплаты. Для проверки с внешней языковой моделью и MCP ЮKassa предусмотрен режим с отдельной базой и ключами.

Если заказ требует решения продавца, агент открывает обращение в кабинете. Ответ приходит в карточку покупателя. После уточнённого сообщения система снова проверяет состав, пересчитывает стоимость и запрашивает подтверждение. Продавец может открыть переписку и отметить заказ исполненным после получения оплаты или предоплаты. Если был только аванс, остаток по-прежнему виден в карточке.

## Быстрый запуск

```sh
docker compose up --build -d --wait
```

Откройте [витрину](http://127.0.0.1:8000/). Отправьте «20 завтраков, из них 5 вегетарианских», затем «Замените два обычных завтрака на вегетарианские». Проверьте итог 7 350 ₽, подтвердите заказ и нажмите «Подтвердить симуляцию». Обновление страницы восстановит оплаченный заказ.

### Подключение второго бизнеса

1. Скопируйте `.env.example` в `.env` и задайте случайный `MERCHANT_SETUP_KEY` от 24 символов. Перезапустите контейнер через `docker compose up -d --wait app`. Ключ передаётся только владельцам, которым разрешено создать магазин.
2. Откройте [кабинет продавца](http://127.0.0.1:8000/merchant). Создайте магазин с адресом `cleaning` и своим кодом владельца от 16 символов. Для доступа к существующей витрине `coffee` администратор задаёт отдельный `COFFEE_OWNER_CODE`. При регистрации владельца кофейни используется этот код.
3. Скачайте пример клининга из кабинета, импортируйте CSV и установите предоплату 30%. Опубликуйте прайс. Заголовок CSV содержит `sku,title,basis,price_kopecks,area_from,area_to`. Для цены за единицу используйте `unit`, для разовой допуслуги `fixed`, для тарифа по площади `area`.
4. Откройте витрину и отправьте «Нужна уборка квартиры 58 м² и чистка духовки». Карточка покажет 5 300 ₽, из них к оплате 1 590 ₽. Подтвердите симуляцию. В кабинете появится заказ со статусом «Предоплата получена».

Для сохранения токенов из кабинета в режиме `live` дополнительно задайте `MERCHANT_VAULT_KEY` в формате Fernet. Сгенерируйте ключ в защищённом локальном окружении и храните его отдельно от резервной копии БД. Кабинет проверяет через MCP наличие `create_payment` и `get_payment` перед сохранением токена. Для кофейни можно использовать ранее поддерживаемый серверный `YOOKASSA_MCP_TOKEN`. Токен из переменной применяется только к кофейне.

Для живого теста скопируйте `.env.example` в `.env`, задайте `APP_MODE=live`, токен **тестового** магазина ЮKassa и ключ выбранного API модели. Compose хранит симуляцию и живой режим в разных файлах базы. Смена режима пересоздаёт контейнер и сохраняет оба журнала.

```sh
docker compose up --build -d --wait app
```

Набор доступных моделей определяется провайдером по `LLM_BASE_URL`. В режиме `live` введите запрос в витрине, подтвердите карточку, откройте страницу ЮKassa, проведите тестовую оплату и вернитесь к заказу. Проверку статуса можно запустить кнопкой в карточке. Схема MCP не позволяет выбирать тестовый магазин в самом вызове. Его определяет выпущенный для этого магазина токен.

Если ответ на создание платежа потерялся, открывается очередь «Сверка платежей». Найдите платёж в кабинете ЮKassa по описанию, которое показало приложение, и введите его ID. Сервер проверит сумму, валюту, описание и статус через `get_payment`. Пока результат не установлен, повторная оплата за эту версию заказа заблокирована.

## Проверки разработки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check app tests
git config core.hooksPath .githooks
```

Последняя команда включает локальный хук проверки staged diff и lint. CI выполняет тесты и проверяет контейнер с сохранением заказа после перезапуска. Содержимое платёжных секретов храните в локальном `.env` или в хранилище секретов сервера.
